# Project review — 13 October 2026

A quick review of `dev` at `becaf04`, written while standing the project up on a second development server (gmkserver). It covers the project's own code and setup: Docker/nginx, `bin/` scripts, the Laravel services app and the `Shi3ld_*` Magento modules and theme. Magento core and `vendor/` were not reviewed.

**Overall:** the custom code is small (about 2,500 lines), tidy and security-conscious. The setup scripts got a clean server from nothing to a working site. Most points below are about repository hygiene and getting ready for a second developer and production, not defects.

## What is working well

- **Input handling in Laravel.** Every write goes through a Form Request with tight rules. Models use explicit `$fillable`, and `status`/`staff_notes` cannot be set from the public form.
- **Staff area.** Separate login, `services_staff` checked in middleware and in the requests, session regenerated on login, `no-store` on staff responses, rate limits on login, quote submission and export.
- **CSV export** neutralises spreadsheet formula prefixes (`= + - @`).
- **Views.** No raw `{!! !!}` output in Blade. Magento templates escape their values; the only unescaped output is rendered child and CMS blocks, which is normal.
- **Enquiry notifications** use a lock, a time budget and retry on the next run instead of losing mail.
- **Adobe hotfix** (`VULN-39341`) is applied automatically after every `composer install`/`update`, and fails loudly if it no longer matches.
- **Secrets** stay out of Git (`.env`, `.secrets/`, `env.php`, certificates). MySQL is not published on the host.

## Recommendations, by priority

### High — fix before the project grows

1. **The test suite fails, and there is no real coverage.** `php artisan test` gives 1 failed, 1 passed. The only tests are Laravel's stock examples, and `tests/Feature/ExampleTest.php` expects `/` to return 200 when it now redirects to `/services`. Suggested first tests:
   - quote submission (valid, invalid, honeypot)
   - staff login, and a non-staff user getting 403
   - enquiry status update
   - CSV export, including formula neutralisation
   - page content edit/publish
   - the notification command's retry behaviour

   Delete or fix the example tests.

2. **About 8,800 Magento skeleton files are committed.** `magento/dev/` (7,400 files), `magento/lib/`, `magento/setup/` and the `magento/pub/` entry points are all copied from `create-project`. Composer (`magento/magento2-base`) already puts these in place, so committing them:
   - roughly doubles every Magento upgrade diff
   - hides the project's own changes
   - lets the committed copy drift from the installed version

   Suggest tracking only `composer.json`/`.lock`, `app/code/Shi3ld`, `app/design/frontend/Shi3ld`, `app/etc/config.php`, `bin/shi3ld-apply-patches.php` and `patches/`, and ignoring the rest. This needs one cleanup commit that both developers agree on, because it removes tracked files.

3. **The read-only Magento database user can read everything.** `docker/mysql/init/01-databases.sh` grants `magento_read` `SELECT ON magento.*`. That includes customer personal data, orders and admin password hashes. Today nothing uses it: `magento_reporting` (in `Shi3ldServiceProvider`) and `MagentoClient` have no callers. Either:
   - remove the connection and the grant until a feature needs them, or
   - grant `SELECT` on just the tables (or a view) that feature needs.

### Medium

4. **Use separate Git identities.** Every commit is authored as `GIT-YM`, so history cannot show who changed what. Each developer can set their own name/email in the repo (`git config user.name` / `user.email`) and still push through the shared account.

5. **Set up a branch workflow and CI.** `main` holds only `web-scope.md`, and all work goes straight to `dev`. With two developers, suggest:
   - short feature branches merged to `dev` by pull request
   - a GitHub Actions job running `php artisan test` and Pint on each PR (there are no workflows yet)
   - `main` reserved for releases

6. **`bin/bootstrap-laravel` changes tracked files on every run.** It always runs `composer require predis/predis` and `laravel/boost`. On gmkserver that upgraded `predis/predis` 3.6.1 → 3.7.0 and `laravel/boost` 2.10.2 → 2.10.3 in `composer.json`/`composer.lock`. Both packages are already in `composer.json`, so the script should run `composer install`. It also reruns `boost:install`, which rewrites `laravel/CLAUDE.md`/`AGENTS.md`.

7. **Enquiry notifications retry forever.** If an acknowledgement cannot be delivered (for example a bad address), `shi3ld:deliver-enquiries` touches the row and retries every minute with no limit. Suggest an attempts counter with a cap and backoff, then flag the enquiry for staff.

8. **The quote form can be used to send mail to any address.** Anyone can submit the form with someone else's email and the site will send them an acknowledgement. The honeypot and `throttle:5,1` limit this. Before go-live, consider a CAPTCHA (Magento already ships reCAPTCHA modules) and keep the acknowledgement free of submitted free text.

9. **The theme's CSS/JS are copied from Laravel.** `bin/sync-site-assets` copies `site.css`, `site.js` and images into the Magento theme, and both copies are committed. Today they are identical. An edit to one side without rerunning the script will drift silently. Suggest either one source with a check in CI, or generating the theme copy and ignoring it.

### Low / housekeeping

10. `magento/pub/opt/magento/var/resource_config.json` is a cache Magento generates at runtime, for an `/opt/magento` path this project does not use. Delete it and ignore `magento/pub/opt/`.
11. `Shi3ld_Integration` creates `shi3ld_integration_outbox`, but nothing reads or writes it yet. That is fine as scaffolding; note it in `docs/development-plan.md` so it is not mistaken for a working integration.
12. Staff enquiry search uses `LIKE '%…%'` without escaping `%`/`_`. This is harmless (validated and length-limited); it only means a search for `%` matches everything.
13. Image tags `opensearchproject/opensearch:3` and `valkey/valkey:9-alpine` float within a major version, while nginx is pinned to `1.30`. Pinning a minor version would make both servers build identically.

## Before production (for later, not now)

These are deliberate development settings, listed so they are not forgotten:
- Magento two-factor authentication is disabled.
- Magento is in developer mode.
- `APP_DEBUG=true` and `LOG_LEVEL=debug`.
- The Laravel responses carry only `X-Content-Type-Options`. Add `X-Frame-Options`/CSP and HSTS at the production edge.
- Uncomment the static-asset cache headers in `docker/nginx/magento.conf`.
- Replace the development mkcert certificate with a real one.

## Change already made on `dev`

`becaf04` moved the server hostname out of the repository. Each server now sets `SITE_HOST` in its own untracked `.env`, and nginx, the certificate script, Magento and Laravel all read it.

**After pulling, rpidevserver needs one line in `.env`:**

```
SITE_HOST=shi3ld.rpidevserver
```

Compose refuses to start without it. The existing `SHOP_URL`/`SERVICES_URL` lines can stay as they are. Then run:

```
docker compose up -d nginx
```

so nginx picks up its new template-based config.
